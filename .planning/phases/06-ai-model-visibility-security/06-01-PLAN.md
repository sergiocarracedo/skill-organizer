# Plan 06-01: Tool model query infrastructure + config + fixture skills

## Objective

Add model-query capability to `agenttools.Tool` definitions so each tool knows how to list its available models. Extend `AgentSelectionConfig` with a `DefaultModel` field. Create dangerous fixture skills in `security/testdata/` for regression testing of the security evaluator.

## Context

Phase 6 requires commands to know which model a tool is using and let the user select one. First, each tool definition must know how to query its model list. OpenCode exposes `opencode models`. Other tools may or may not have equivalent commands. The `Tool` struct already uses per-tool function fields (`Args`, `PlanArgs`) — `ListModels` follows the same pattern. Fixture skills are needed for testing `check-security` against dangerous patterns.

## Tasks

### Task 1: Add ListModels and VersionQuery to Tool struct

<files>
- packages/cli/internal/agenttools/agenttools.go
</files>

<action>
Add two fields to the `Tool` struct:

```go
type Tool struct {
    ID          string
    Name        string
    Binaries    []string
    Description string
    Args        func(prompt string) []string
    PlanArgs    func(prompt string) []string
    ListModels  func(binary string) ([]string, error)    // NEW
    ModelArgs   func(model string, prompt string) []string // NEW
    VersionArgs []string                                   // NEW
}
```

`ListModels` takes the resolved binary path and returns available model names. `ModelArgs` returns the CLI args to pass the selected model (e.g. OpenCode: `--model provider/model` then prompt). `VersionArgs` is the CLI args to get the tool's version. All new fields are optional — nil means "not supported".

Add a helper function:

```go
func QueryToolModels(tool InstalledTool) ([]string, error)
```

`QueryToolModels` calls `tool.Tool.ListModels(tool.Binary)` if ListModels is non-nil. Returns `nil, nil` if ListModels is nil. Wraps errors with context.

Update `InstalledTool` docs to reflect that Binary is resolved at detection time.
</action>

- QueryToolModels returns nil, nil for tools with nil ListModels
</verify>

### Task 2: Define per-tool model queries in supportedTools

<files>
- packages/cli/internal/agenttools/agenttools.go
</files>

<action>
For each tool in `supportedTools`, set `ListModels`:

1. **OpenCode** (`ID: "opencode"`): `ListModels: func(binary string) ([]string, error) { ... }`
   - Runs `binary` with args `[]string{"models"}` (i.e. `opencode models`)
   - Executes via `exec.Command(binary, "models")`, captures stdout
   - Splits output by newlines, filters empty lines
   - Returns the list of non-empty lines (each line is `provider/model` format)
   - If command fails, returns `nil, fmt.Errorf("query opencode models: %w", err)`

2. **All other tools** (`claude`, `codex`, `cursor`, `antigravity`): leave `ListModels: nil`
   - These don't expose a model list via CLI

For `ModelArgs`:
- **OpenCode**: `ModelArgs: func(model string, prompt string) []string { return []string{"run", "--model", model, prompt} }`
  - Produces: `opencode run --model anthropic/claude-sonnet-4 "prompt text"`
- All others: leave nil (no model passing for tools without model support)

For `VersionArgs`:
- OpenCode: `VersionArgs: []string{"--version"}`
- All others: leave nil (version query not needed for Phase 6 scope)

The `opencode models` runner should use `exec.Command` directly (not `detectToolBinary` — the `binary` parameter is already resolved at detection time).
</action>

<verify>

- Other tools have ListModels: nil
- Running QueryToolModels on a mock OpenCode tool returns known model names
</verify>
