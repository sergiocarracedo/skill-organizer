# Plan 06-03: Security rating in status tree with content-hash freshness

## Objective

Add risk score display to the `status --tree` output. Each skill line shows a `[risk: N]` tag colored by score level. Unevaluated skills show `[risk: uncheck]` in yellow. Store a content hash at evaluation time; if files change, the score is shown as stale.

## Context

Phase 1 stores risk scores in `ManagedMetadata` (risk-score, risk-evaluated-at, risk-evaluator, risk-reason). The status tree currently shows state, installed version, and update info — but no risk data. Phase 6 adds the risk tag and a content-hash freshness check.

Add a helper function in `frontmatter.go` or a new file `packages/cli/internal/skills/hash.go`:

```go
// ComputeSkillHash computes SHA-256 of a skill's content files.
// Reads all files in the skill directory, concatenates (sorted by filename),
// and returns hex-encoded SHA-256. Excludes the SKILL.md frontmatter metadata
// block (only hashes the content body and non-metadata files).
func ComputeSkillHash(skillDir string) (string, error)
```

Exclude `metadata.skill-organizer` YAML keys from the hash (they contain the hash itself plus the risk score — a circular dependency). Strategy: parse SKILL.md, extract the body (everything after `---`), hash that + any other files sorted by name.

In `cmd/skill_security.go`, in the processing loop after a `SkillResult` is stored:

```go
hash, err := skills.ComputeSkillHash(skill.Dir)
if err == nil {
    updates.RiskSourceHash = hash
    skills.UpdateManagedMetadata(skill, updates)
}
```

If hashing fails (unlikely), log a warning and continue — the score is still stored without the hash.

- `TestComputeSkillHash_ChangesWhenContentChanges`: modify a file, hash changes.
- `TestComputeSkillHash_ExcludesMetadata`: adding a risk-score to metadata doesn't change the hash.

Add integration test in skill_security_test.go:
- `TestCheckSecurity_StoresRiskSourceHash`: run check-security on a fixture, verify RiskSourceHash is stored in metadata.
</action>

### Task 4: Render risk tag in status tree

<files>

<action>
Modify `formatSkillLabel()` in `status_render.go` to render a risk tag.

After the existing installed/update info, append a risk tag:

1. If `entry.RiskEvaluator == ""` (unevaluated):
   - Append ` [risk: uncheck]` in pterm.FgYellow (yellow)

2. If `entry.RiskSourceHash != ""` and current hash doesn't match:
   - Append ` [risk: N (stale)]` in pterm.FgYellow (yellow)

3. If `entry.RiskScore` is set and hash matches (evaluated, fresh):
   - Score 0–29: append ` [risk: N]` in pterm.FgGreen (green)
   - Score 30–69: append ` [risk: N]` in pterm.FgYellow (yellow)
   - Score 70–100: append ` [risk: N]` in pterm.FgRed (red)

Import `skills.ComputeSkillHash` to compute the current hash for comparison. Computing the hash for every skill on every status run is acceptable (it's local file I/O, fast).

The `statusTreeLine` struct or rendering function needs to carry the risk info. Modify `buildStatusTreeLines` to pass risk info through the tree structure. The `levelInfo` or equivalent struct needs `riskScore int`, `riskEvaluator string`, `riskSourceHash string`.

- `TestFormatSkillLabel_ShowsStaleWhenHashMismatch`: hash mismatch shows `[risk: N (stale)]`.
