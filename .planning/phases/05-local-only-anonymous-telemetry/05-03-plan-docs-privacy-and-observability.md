# Plan 05-03: Docs (PRIVACY.md + OBSERVABILITY.md updates)

## Objective

The privacy posture is documented in a new top-level
`PRIVACY.md` (4 sections, user-facing legal language), and
`OBSERVABILITY.md` is updated to reflect the 5-field schema,
the build-time backend, and a link to `PRIVACY.md`. The
observability byte-for-byte example-block test is updated to
match the 5-field shape and the new 6-section structure.

This plan depends on 05-01 (the internal `Event` is now
5 fields) and 05-02 (the CLI surface is final) so the docs
describe the actual shipped behavior.

## Context

`OBSERVABILITY.md` is currently 232 lines, 7 H2 sections,
with a 7-field example block and a "Backend: New Relic"
sub-section explaining the env-var wiring. None of that
matches the v0.x Phase 5 design.

`PRIVACY.md` does not exist yet; the privacy text is
embedded in `OBSERVABILITY.md`'s "Privacy guarantees" H2
section, which is too technical and too short for a
user-facing legal document.

The user's design intent (per `05-CONTEXT.md` Areas C and
the discussion log): privacy language is in a separate file
so it's easier to share with a DPO; the schema-change
protocol is a first-class section so future schema changes
are explicit and versioned.

<name>Create PRIVACY.md with the 4 required sections</name>
<files>PRIVACY.md (new)</files>
<action>
Create `PRIVACY.md` at the repo root with the following
4 H2 sections in order:

1. **Field-by-field disclosure**
   - A markdown table with 3 columns: Field, Type, Why it's anonymous.
   - 5 rows for command, exit_status, timestamp, version, event_id.
   - The "Why it's anonymous" column per field:
     - `command`: cobra subcommand name; intrinsic to the call, not user-configurable.
     - `exit_status`: 0 or 1; the cobra exit code, not user-supplied.
     - `timestamp`: RFC3339 UTC; bucketed server-side if the maintainer needs hour granularity.
     - `version`: the CLI semver; a public string the user can see in `skill-organizer --version`.
     - `event_id`: 32 hex chars from 16 random bytes per event, generated by `ulid.Make` (crypto/rand); per-event, not per-user, so it cannot link two events.
   - Add a closing paragraph: "No fields beyond these 5 are ever emitted. See the 'Schema-change protocol' section for what we will never collect."

2. **Legal basis and data retention**
   - Sub-section "Legal basis": "We rely on **consent** (GDPR Art. 6(1)(a)). The first-run prompt asks the user to opt in; the answer is sticky. The user can opt out at any time by running `skill-organizer telemetry disable`."
   - Sub-section "Data retention on the device": "The on-device buffer (`<appDir>/telemetry-buffer.jsonl`) is a 1 MB JSONL spool with FIFO eviction. Events that cannot be sent (network down) stay in the buffer until they are sent or until the buffer rotates. The buffer is deleted by `skill-organizer telemetry wipe`."
   - Sub-section "Data retention on the backend": "The chosen processor (New Relic) retains ingested events for 8 days under the free-tier account. After 8 days, events are dropped from the New Relic Insights UI; raw storage is deleted per the New Relic DPA. We do not back up, mirror, or export the data to any other system."

3. **Data-controller statement**
   - "The **data controller** is the maintainer of the `skill-organizer` CLI (see the `CODEOWNERS` file or the GitHub repository's `OWNERS` for the current individual or team)."
   - "The **data processor** is New Relic, Inc. (US). The processor's DPA is executed as part of the maintainer's New Relic account signup; the maintainer can produce a copy on request."
   - "**Contact:** open a GitHub issue on the [skill-organizer repository](https://github.com/sergiocarracedo/skill-organizer). For privacy-specific requests (data access, deletion, complaint), use the issue title prefix `privacy:`."

4. **Schema-change protocol**
   - "The 5 fields above are the **only** fields the project will ever emit in v0.x. The following are **explicitly excluded** and will not be added without a new `OBSERVABILITY.md` and `PRIVACY.md` version, a new event type, and a release-note entry:"
   - A bulleted list: file paths, command arguments, environment variable values, usernames, hostnames, machine serials or hardware IDs, IP addresses, file contents, source code or text from the user's project, anything that could identify a person or organization, anything that could identify a specific file or machine.
   - "Any new field is a **breaking change** to the privacy contract. It will be proposed via the standard `enhancement` issue template and reviewed by the maintainer."

5. (Optional) Closing: "This document is informational. It does not constitute legal advice. For a binding data-processing agreement, contact the maintainer."

Note: the 4th "H2" is the last required section. The closing paragraph at the end is plain text, not a section header.
</action>
